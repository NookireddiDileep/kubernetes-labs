# 📖 Problem Statement

A Pod remains in the **Pending** state because Kubernetes cannot find a node that satisfies the scheduling requirements defined in the Pod specification.

In this lab, the Pod requests a node with the label:

```
disktype=ssd
```

Since no node in the cluster has this label, the Scheduler cannot assign the Pod to any node.

---

# 📝 Broken Manifest

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pending-demo
spec:
  nodeSelector:
    disktype: ssd
  containers:
  - name: nginx
    image: nginx:latest
```

---

# 🚀 Deploy the Pod

```bash
kubectl apply -f pending-pod.yaml
```

Verify the Pod status:

```bash
kubectl get pods
```

Expected output:

```
pending-demo   0/1   Pending
```

---

# 🔍 Investigation Steps

## 1. Check Pod Status

```bash
kubectl get pods
```

Purpose:

- Verify the Pod is in the Pending state.
- Confirm that the Pod has not been scheduled.

---

## 2. Describe the Pod

```bash
kubectl describe pod pending-demo
```

Purpose:

- Review Pod Events.
- Identify scheduling failures.
- Understand why no node was selected.

Typical Event:

```
0/1 nodes are available:
1 node(s) didn't match Pod's node selector.
```

---

## 3. Review Cluster Events

```bash
kubectl get events --sort-by=.metadata.creationTimestamp | grep pending-demo
```

Purpose:

- Observe Scheduler-generated events.
- Confirm the scheduling failure reason.

---

## 4. Verify Node Labels

```bash
kubectl get nodes --show-labels
```

Purpose:

- Display labels assigned to cluster nodes.
- Verify that no node has the required label.

---

# 🔬 Root Cause Analysis

The Pod specifies the following scheduling requirement:

```yaml
nodeSelector:
  disktype: ssd
```

The Scheduler compares this requirement against all available nodes.

Since no node contains the label:

```
disktype=ssd
```

the Scheduler cannot assign the Pod to any node.

As a result, the Pod remains in the **Pending** state.

---

# 🔄 Scheduling Workflow

```
Pod Created
      │
      ▼
API Server Stores Pod
      │
      ▼
Scheduler Evaluates Nodes
      │
      ▼
No Matching Node Found
      │
      ▼
Scheduling Failed
      │
      ▼
Pod Remains Pending
```

---

# 🛠️ Resolution

Remove the invalid `nodeSelector` from the Pod manifest.

Updated manifest:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pending-demo
spec:
  containers:
  - name: nginx
    image: nginx:latest
```

Delete the existing Pod:

```bash
kubectl delete pod pending-demo
```

Deploy the updated manifest:

```bash
kubectl apply -f pending-pod.yaml
```

---

# ✅ Verification

Verify that the Pod is now running:

```bash
kubectl get pods
```

Expected output:

```
pending-demo   1/1   Running
```

# 🚀 Production Best Practices

- Use `nodeSelector` only when specific node placement is required.
- Prefer `nodeAffinity` for more flexible scheduling policies.
- Maintain consistent node labeling across clusters.
- Monitor Pending Pods as part of cluster health checks.
- Review Scheduler events before modifying workloads.
- Validate scheduling constraints during deployment testing.

# 🎤 Interview Questions

### Q1. What does the Pending state indicate?

The Pod has been accepted by the API Server but has not yet been scheduled onto a node.

---

### Q2. Which Kubernetes component schedules Pods?

The **Kubernetes Scheduler**.

---

### Q3. How do you troubleshoot a Pending Pod?

1. Check Pod status.
2. Describe the Pod.
3. Review Events.
4. Verify node labels.
5. Check resource availability.
6. Check taints and tolerations.
7. Correct scheduling constraints.

---

### Q4. What is a nodeSelector?

A `nodeSelector` restricts a Pod to run only on nodes with matching labels.

---

### Q5. What is the difference between nodeSelector and nodeAffinity?

- **nodeSelector** supports exact label matching.
- **nodeAffinity** provides more advanced scheduling rules such as preferred and required placement.

---

### Q6. What are other common reasons for Pending Pods?

- Insufficient CPU or memory resources
- Taints without matching tolerations
- Unbound PersistentVolumeClaims
- Unsatisfied node affinity rules
- No schedulable nodes available
